# Screen Helper 8.2 — переносимая настройка OpenAI

`Setup-OpenAI.cmd` открывает настройку сервиса OpenAI и модели gpt-5.4-mini.
Нужен собственный оплаченный API-ключ; в архиве ключа нет. Настройка и пополнение
счёта выполняются владельцем аккаунта. Локальный ключ не загружается в GitHub.
GPT-5.4 mini поддерживает изображения и структурированный ответ через Responses API.
Режимы Быстро/Сбалансированно/Тщательно задают low/medium/high для этой модели.
При ручном выборе другой модели проверьте поддерживаемые ею параметры.

Ошибки OpenAI «нет баланса/квоты» и «слишком много запросов» различаются.
В отчёте сохраняются возвращённые API числа токенов. Эти числа не являются
остатком счёта и не устанавливают общий денежный лимит аккаунта.
OpenAI проверен автономными тестами с имитацией HTTP; живого ключа OpenAI сейчас
нет, поэтому скорость и точность оплаченной модели не подтверждены.
Официальная модель: https://developers.openai.com/api/docs/models/gpt-5.4-mini
Функции Gemini, локальных графовых вычислений и отмены сохранены.

# Screen Helper 8.1

Исправлен реальный отказ разбора ответа: если модель вернула «P1. текст вопроса»
или «2) 7» в поле метки, явный номер извлекается по разделителю. Содержание ответа
не угадывается; повторяющиеся метки и неоднозначные графы по-прежнему отклоняются.

Основная модель Gemini 3.8 остаётся доступной. Для новых настроек предлагается
резерв gemini-2.5-flash: при временном сбое или ожидании основной дольше 15 секунд
используется остаток общего бюджета. Для резерва автоматически выбран совместимый
GenerateContent API. Резерв можно отключить, очистив поле в Setup. При 401/403/429
переключения нет. Это другая модель с другими возможностями; её имя показывается
в панели и отчёте. Гарантии одинаковой точности моделей нет.

После временного HTTP 500/502/503/504 выполняется максимум один повтор с паузой
в пределах общего лимита; 429 и ошибки ключа не повторяются. Ключ остаётся локальным.
Режим рассуждений, полный снимок, распознавание нескольких вопросов и проверка графов
сохранены. Основная модель и резерв видны в Control.cmd.

Проверки на текущем ключе: Gemini 3.8 не ответил на минимальный запрос за 35 секунд
ни через v1, ни через v1beta. Резерв вернул правильные ответы на три вопроса ДАА
с направленным графом и на рекуррентную сложность. Эти проверки не гарантируют
точности на любых вопросах или работы в OES. Переносимая сборка предназначена
для Windows x64, требует интернет и собственный доступный API-ключ на другом ПК.

В GitHub загружайте файлы из архива исходников или публичную переносимую сборку.
Не загружайте папку установленной программы целиком: в ней находится ваш ключ.

# Screen Helper — Windows

Версия 8.0 — управление запросами и диагностика.

- `Control.cmd` открывает панель: состояние, результат, запуск/остановка помощника,
  отмена, настройки, локальная проверка без API и отдельная проверка AI на примере 2+2.
- Запрос выполняется в отдельном процессе. Общий лимит по умолчанию — 60 секунд,
  включая ожидание и резерв. По истечении лимита локальный процесс завершается.
  Старый сохранённый безлимит автоматически заменяется на 60 секунд. После миграции
  можно явно выбрать 0 в Setup, сохранив возможность отмены.
- `Ctrl+Alt+X` отменяет локальное ожидание; если сочетание занято, есть кнопка панели.
  Отмена закрывает соединение, но не гарантирует отмены уже принятой работы или оплаты
  на стороне провайдера. `Ctrl+Alt+H` только скрывает показ, как и раньше.
- Одновременно выполняется один управляемый запрос. Повторного автоматического
  обращения к той же перегруженной модели нет. После перегрузки/тайм-аута/429
  действует пауза 60 секунд. Новый ключ не обходит квоты проекта провайдера.
- Резервная модель включается явно в Setup. Резерв вызывается один раз только после
  временного сбоя и в пределах общего бюджета. При ошибке ключа, доступа или квоты
  перехода к резерву нет. Доступный и точный резерв для текущего ключа не подтверждён,
  поэтому в поставляемых настройках резерв пустой.
- Точно одинаковые снимки могут использовать положительный ответ из памяти в течение
  минуты; изменённое изображение, модель, режим или ключ не получают этот ответ.
  Ошибки и «?» не кэшируются. Проверка AI в панели всегда выполняет реальный запрос.
- Сохранённый ключ имеет приоритет перед переменной окружения. Ключи не попадают
  в командную строку дочернего процесса, архивы, статус или журналы.

Локальные проверки подтверждают работу программы, а не доступность AI или точность
на любых университетских вопросах. 503, ограничения квоты 429 и сбои сети могут
по-прежнему мешать получить ответ. Страница и программа не подтверждают обход OES.

Версия 7.7: для Gemini 3 по умолчанию используется Interactions API с текущей
схемой steps/model_output. В Setup сохранён выбор GenerateContent для совместимости.
Запросы Interactions отправляются с store=false; итог берётся только из текстового
вывода модели при status=completed. Незавершённый ответ не показывается как готовый.
Потоковый переключатель относится только к GenerateContent.
При HTTP 503 с явным сообщением high demand/overloaded выводится
«API: Gemini перегружен (503)». Другие 503 остаются общей ошибкой сервиса.
Смена протокола не гарантирует доступность модели. Работоспособность при текущей
нагрузке проверяется реальным запросом; офлайн-проверки не доказывают её.

Версия 7.6 исправляет устаревшую проверку ключа. Google Auth keys (в том числе AQ.)
и прежние AIza принимаются; сервис и модель в режиме «Авто» определяются заново.
В Setup появился явный выбор Google Gemini / OpenAI / Авто по ключу. Если формат
ключа неизвестен программе, выберите нужный сервис вручную — действительность
ключа проверяет API, а не предположение о префиксе. Пробелы по краям и окружающие
кавычки убираются; звёздочки вместо ключа и переносы строк не принимаются.
Google получает ключ только в x-goog-api-key, не в адресе запроса.
Сохранение настроек не означает успешной проверки ключа или устранения HTTP 503.

Версия 7.5: временный индикатор показывает фактический этап и прошедшие секунды:
подготовка снимка → отправка/ожидание API → получение данных → проверка → результат.
Это не проценты готовности модели и не просмотр её внутренних рассуждений.
Если долго показано «Отправка / ожидание API», данных ответа ещё нет; нельзя
считать всё это время рассуждениями AI. Настройка «Показывать этап и время запроса»
отключает индикатор. Ctrl+Alt+F8 показывает состояние, когда ответа ещё нет.
`process-status.json` содержит текущий этап и время, `last-result.json` — итог и
замеры захвата, кодирования, сети и локальной проверки. Ключей и снимков в них нет.

Экспериментальное потоковое получение Gemini включается отдельно: оно помогает увидеть поступление данных,
но не гарантирует более быструю генерацию. Итог показывается после завершения
и проверки JSON. Незавершённый поток не превращается в ответ. Переключатель в Setup
позволяет выбрать поток вместо обычного запроса, используемого по умолчанию.
Режимы Gemini: «Сбалансированно» (MEDIUM для Gemini 3 Flash), «Тщательно» (HIGH),
«Быстро» (LOW, возможна потеря точности), «Настройки самой модели» (без переопределения).
MEDIUM уже является стандартным режимом некоторых моделей и сам по себе не обещает
ускорения относительно предыдущей версии. Лимита длины вывода по-прежнему не задаём.

В поддерживаемых задачах граф сначала распознаётся; вычисление выполняется локально,
без повторного решения того же алгоритма моделью. Добавлены расстояние Беллмана—Форда
и расстояние BFS (число рёбер). Неясные данные, достижимый отрицательный цикл или
неоднозначное сопоставление с вариантом дают «?». Это не исправляет ошибки OCR.
Для остальных университетских задач решает модель; гарантии правильности нет.
Совместимость с конкретным прокторингом и обход его защиты не подтверждены.

Версия 7.4: временный режим «Оставлять ответ до скрытия» в Setup.
В нём результат или ошибка API остаются видимыми до Ctrl+Alt+H, следующего запроса
Ctrl+Alt+S или выхода Ctrl+Alt+Q. Повторный показ Ctrl+Alt+F8 тоже остаётся видимым.
Сообщения готовности и ожидания по-прежнему кратковременные. Для возврата к показу
на 2 секунды снимите флажок в Setup; настройка применяется со следующего запроса.
Этот режим меняет только время показа и не исправляет ошибки API.

Версия 7.3: по умолчанию нет локального тайм-аута запроса (раньше — 45 секунд).
Не задаются max_output_tokens/maxOutputTokens, thinkingBudget или thinkingLevel:
модель использует собственные значения по умолчанию. Это не снимает ограничений
модели и сервиса, не устраняет HTTP 503 и не гарантирует правильность ответа.
В Setup «Ожидание API» = 0 означает отсутствие нашего тайм-аута; положительное
значение задаёт ожидание 1–3600 секунд. Расход и время могут увеличиться.
При зависшем соединении ожидание может продолжаться неограниченно; Ctrl+Alt+Q
завершает процесс. Закрытие соединения не гарантирует отмены уже принятого запроса
у провайдера. Повторное нажатие S во время запроса не создаёт новую платную задачу.

Для вариантов A/B/C/D выводится только выбранная буква; для 1/2/3/4 — цифра.
Кириллические метки сохраняются как напечатаны. Модель отдельно возвращает
прочитанные метки, и ответ сверяется с ними. Несовпадение даёт «?». Это проверка
формата, а не гарантия правильного распознавания или решения. Для нескольких
вопросов показываются отдельные строки. Неполный ответ API не выдаётся за готовый.
После захвата кратко появляется «AI: working»; готовый ответ показывается 2 секунды.
Ctrl+Alt+F8 во время ожидания показывает статус, после завершения — последний ответ.

Захват активного окна по умолчанию, включая второй монитор.
Для захвата всего его монитора включите флажок в Setup. Это обычный снимок видимой
области: перекрытое окно, свёрнутое окно или содержимое вне экрана не считывается.
Сайту не нужна специальная интеграция; Chrome/Edge/Firefox отдельно не изменяются.
Проверена логика координат и нативного окна; все браузеры и сайты не проверены.
Защищённые поверхности могут блокировать снимок; обход такой защиты не реализован.
Одноцветный пустой снимок даёт `Capture: blank image` и не отправляется в API.

При HTTP 500/502/503/504 запрос повторяется один раз с паузой минимум 2 секунды,
с учётом Retry-After (до 8 секунд).
Повторов при 401/403/404/429 и сетевом тайм-ауте нет. Временная недоступность сервиса
503 не устраняется локальным скриптом. Ключ и модель автоматически не заменяются.
Повторный запрос может расходовать квоту. Ctrl+Alt+F8 повторно показывает последний
результат текущего запуска на 2 секунды, без снимка и без нового API-запроса.

Модель Google по умолчанию — gemini-3.8-flash.
Список models.list не гарантирует доступ к generateContent. API:model означает
HTTP 404 и требует проверки конкретного ответа API, а не смены ключа наугад.

расстояние и порядок Дейкстры, порядок Кана. Противоречивые данные дают `?`.
`last-recognition.json` показывает прочитанные вопросы, вершины, направления и веса;
сопоставьте их с изображением. Алгоритм не исправляет сам по себе ошибку OCR.
Теоретические и прочие задачи остаются непроверенными ответами модели.

## Первый запуск на другом компьютере

**Переносимый архив `screen-helper-portable-v8.2.zip`: Windows 10/11 x64,
без установленного Python и без прав администратора.**

1. Распакуйте весь архив в доступную для записи папку.
   Нажмите правой кнопкой по ZIP → **Извлечь всё**. Не запускайте CMD прямо из ZIP.
   В новой переносимой версии рядом с EXE обязательно должна остаться папка `_internal`.
2. Запустите `Setup.cmd`. Откроется окно настройки: вставьте свой ключ OpenAI API
   или Google AI Studio (Gemini). Программа определит сервис по формату ключа.
   Если Ctrl+V не срабатывает, нажмите **Вставить ключ** или правой кнопкой по полю →
   **Вставить ключ**. Также поддерживается Shift+Insert. Поле скрывает символы;
   счётчик под ним подтверждает вставку. **Показать** временно раскрывает текст на вашем экране.
   Для OpenAI модель по умолчанию `gpt-4.1-mini`, для Google — `gemini-3.8-flash`.
   Старое сочетание ключа Google с моделью GPT автоматически исправляется.
   Можно указать другую модель того же сервиса с поддержкой изображений.
   Нужны доступ к выбранной модели и доступный API-баланс/лимит.
3. Запустите `Start.cmd`. После запуска CMD можно закрыть.
4. Сначала проверьте работу на обычной странице с примером вопроса.

Из CMD: перейдите в распакованную папку и выполните `Start.cmd`.
Интернет требуется для ответа ИИ, а не для запуска программы.
Версия v2 запускает встроенную среду из `_internal` без распаковки при каждом запуске.

Ключ можно заранее создать на своём устройстве:
[страница API-ключей](https://platform.openai.com/api-keys).
Для Google используйте [Google AI Studio](https://aistudio.google.com/api-keys).
Получать новый ключ на каждом компьютере не требуется. Введите его в окне настройки.
Не добавляйте ключ ни в исходники, ни в архив, опубликованный в GitHub.

Для запуска из **исходников** нужен Python 3.11+ с **Add Python to PATH**;
`Setup.cmd` сам создаст `.venv` и установит зависимости, если рядом нет EXE.

## Управление

| Клавиши | Действие |
|---|---|
| Ctrl+Alt+S | Сделать снимок и получить ответ |
| Ctrl+Alt+F8 | Повторно показать последний результат без обращения к API |
| Ctrl+Alt+H | Убрать ответ, отменить показ результата текущего запроса |
| Ctrl+Alt+Q | Завершить процесс |

Во время запроса повторное Ctrl+Alt+S игнорируется. Ответ появляется после сети
и обработки моделью и исчезает через **2 секунды**. Чёрные символы без фона
появляются справа снизу рабочей области, размер шрифта по умолчанию 11 пикселей.
На тёмном фоне чёрный текст может быть плохо виден.
Для одного вопроса показывается только метка ответа. Для нескольких — отдельные
строки с номерами: `A2: 4`, `A3: 1`, `A4: 2`. Цифровые варианты не заменяются буквами.
Нечитаемый или обрезанный вопрос помечается `?`, а не угадывается.
Скрытие не отменяет уже отправленный
API-запрос. Если клавиша занята другой программой, скрипт сообщит об этом и завершится.
Повторный запуск не создаёт второй экземпляр. Прав администратора не требуется.
Если Ctrl+Alt+F8 занята, повторный показ недоступен, но программа продолжает работать.

## Настройки и данные

`config.local.json` создаётся локально. В v6 время показа фиксировано на 2 секундах,
`font_size` — размер текста, `overlay_margin` — отступ от края (по умолчанию 12).
Для смены ключа/модели повторите `Setup.cmd`.
Можно использовать переменную окружения `OPENAI_API_KEY` или `GEMINI_API_KEY`
в соответствии с выбранным сервисом вместо сохранённого ключа.
Ключ в локальном JSON хранится открытым текстом; держите его в своей учётной записи.

В GitHub загружайте только файлы этой папки, исключая `.venv`, `config.local.json`
и `__pycache__` — они перечислены в `.gitignore`. Не используйте принудительное
добавление игнорируемых файлов. Репозиторий не должен содержать API-ключи.

Снимок содержит активное окно или его монитор, включая видимые личные данные. Он отправляется
только по Ctrl+Alt+S; автоматической съёмки, записи камеры и микрофона нет.
На диск снимки не сохраняются. Для OpenAI `store: false` отключает хранение объекта Response,
но не означает гарантированного отсутствия всех журналов у провайдера API.
При выборе Gemini запросы отправляются напрямую в Google; действуют условия Google.

Ошибки в окне: `key` — неверный ключ; `access` — нет доступа; `model` — модель
недоступна; `quota/limit` — баланс или лимит; `timeout` — истекло время ожидания;
`service unavailable (503)` — сервер временно не смог обработать запрос;
`connection reset` — соединение принудительно закрыто; `DNS` — имя сервера не найдено;
`TLS certificate` — ошибка проверки сертификата. Проверка сертификатов не отключается.
Запустите `Network.cmd` для независимой проверки связи с выбранным сервисом без ключа,
снимков экрана и платного запроса к модели. Результат — `network-check.json`.
HTTP 401 при этой проверке ожидаем и подтверждает получение HTTP-ответа,
но не проверяет действительность вашего ключа и доступ к модели.
`ApiTest.cmd` проверяет ключ и модель одним примером (до двух HTTP-попыток): программа
создаёт картинку с вопросом «2+2», отправляет выбранному сервису и ожидает B.
Рабочий стол не снимается. Может расходоваться квота/баланс API.
Отчёт — `api-check.json`, без ключа. `ok: true` подтверждает этот пример, а не
достоверность любых будущих ответов и не совместимость с OES.
`MultiTest.cmd` выполняет **три примера с реальными API-запросами** по образцам с 1, 2 и 3 вопросами.
При временных серверных ошибках возможен один повтор каждого запроса.
Снимок рабочего стола не делается. `multi-check.json` содержит ответы, ожидаемые
результаты и время; ключа в нём нет. Для всех трёх случаев ожидается `all_ok: true`.
Для диагностики из папки выполните `.venv\Scripts\python.exe helper.py`.

## Сборка и проверка

Исходники проверены на Windows с помощью
`python -m unittest discover -v`.
Для самостоятельной сборки установите Pillow и PyInstaller, выполните:

```cmd
python -m PyInstaller --noconfirm --clean --onedir --windowed --exclude-module numpy --name ScreenHelper helper.py
```

Результат — папка `dist\ScreenHelper` с EXE и `_internal`. Скопируйте рядом с EXE
`Start.cmd`, `Setup.cmd`, `Check.cmd`, `Network.cmd`, `ApiTest.cmd`, `MultiTest.cmd`,
папку `samples`, `README.md`, `.gitignore` и упакуйте всю папку.
Для публикации исходников используйте подготовленный `screen-helper.zip`:
он включает транспорт, захват, вычислитель графов и тесты. Локальная конфигурация исключена.
Файлы CMD рассчитаны на сборку Python 3.13 x64. Ключ и конфигурация в сборку не включаются.
Не загружайте EXE в репозиторий через автоматический поиск всех локальных файлов:
используйте подготовленный переносимый ZIP в GitHub Releases. Один EXE без `_internal` не работает.

`ScreenHelper.exe --self-check` проверяет встроенные зависимости, регистрацию клавиш
и маленькое окно без обращения к API и без снимка реального рабочего стола.
Результат записывается в `self-check.json`. Эта проверка не подтверждает работу с OES.
Для проверки двойным щелчком есть `Check.cmd`; сначала завершите работающий экземпляр.
