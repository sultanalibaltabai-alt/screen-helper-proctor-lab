# Общий ИИ без API-ключа на каждом ПК

Сервис уже опубликован:
https://study-tools-cloud-sultan-1109.satinwaterlily4.chatgpt.site
Статус: /health. Gemini уже подключён через runtime secret, SERVICE_ENABLED=true.
Контрольный запрос через готовый EXE и этот сервер вернул B) 4 за 4,28 секунды,
HTTP 200. Используется gemini-3.5-flash-lite. OpenAI пока не подключён.
Ниже — порядок будущей смены провайдера/ключа; повторять настройку сейчас не нужно.

На компьютере, скачавшем ZIP, находится только адрес сервиса. При первом запросе
приложение автоматически получает ограниченный токен установки и защищает его Windows DPAPI.
Этот токен не является ключом Gemini/OpenAI. Общий ключ провайдера хранится только на сервере.
Нельзя встраивать его в EXE, исходники, ZIP или раздавать всем пользователям.

## Что требуется один раз от владельца

1. Выбрать Gemini или OpenAI. Для OpenAI открыть свой OpenAI Platform → Billing,
   пополнить доступный API-проект на $5, если такая сумма предлагается, и проверить
   итоговую стоимость. $5 — расходуемый баланс, не безлимит и не подписка ChatGPT.
   Доступность оплаты/модели определяется аккаунтом; программу нельзя оплатить лимитом Codex.
2. Создать собственный ключ. Не присылать его в чат. Для OpenAI через Codex сначала
   использовать плагин OpenAI Developers и его openai-platform-api-key skill;
   если он недоступен, подключить его. Ключ добавляется как runtime secret Sites
   через штатные инструменты, а не через публикацию файла.
3. У существующего сервиса указать секрет OPENAI_API_KEY, AI_PROVIDER=openai,
   AI_MODEL=gpt-5.4-mini и SERVICE_ENABLED=true. Для Gemini вместо этого использовать
   GEMINI_API_KEY, AI_PROVIDER=gemini, AI_MODEL=gemini-3.5-flash-lite. Сохранить IP_HASH_SECRET
   и существующие лимиты. Не добавлять оба ключа без необходимости.
4. После изменения runtime secret развернуть существующую сохранённую версию Sites,
   чтобы применить новый env revision. Не создавать новый Site, адрес должен сохраниться.
5. Проверить /health: ready=true означает наличие конфигурации, не подтверждение
   доступа к платной модели. Затем разрешить один контрольный API-запрос через
   Control.cmd → «Проверить AI». Синтетический вопрос 2+2, ожидается B) 4; рабочего
   стола в этой проверке нет. Запрос может расходовать общий баланс/квоту.

После настройки владельцем тот же ZIP начнёт использовать общий сервер на других
Windows x64 компьютерах без ввода личного API-ключа. Интернет и доступ к серверу нужны.
Свой Gemini также доступен через Setup-Gemini.cmd, OpenAI — через Setup-OpenAI.cmd.

## Лимиты и данные

По умолчанию: 50 принятых попыток за всё время, 20 в сутки для сервиса, 10 в сутки
для установки и 2 в минуту для установки. Это счётчики запросов, а не денежный баланс.
Не обещается, что $5 хватит на 50 ответов: цена зависит от модели, изображения и токенов.
Ключ и баланс проверяются отдельно у провайдера. Публичный сервис с общим балансом
может быть исчерпан другими пользователями; владелец может выключить SERVICE_ENABLED.

Счётчики D1 сохраняются между перезапусками. Новая установка не сбрасывает общий лимит.
Не поднимать лимиты и не менять QUOTA_NAMESPACE без явного решения владельца:
новый namespace сознательно начинает новый общий счётчик. Не повторять автоматически
принятый платный запрос. Повтор одного Idempotency-Key возвращает 409 без нового вызова.
Неудачная принятая попытка тоже учитывается консервативно; это не отчёт об оплате.

Размер изображения ограничен 2 МБ и 12 млн пикселей, при необходимости клиент его
уменьшает. Ответ провайдера ограничен 8000 output tokens. Не помещающиеся/неполные
ответы не угадываются. На ПК нормальный режим не сохраняет историю; сервер не
записывает изображения, вопросы и ответы в D1. В базе только хеши токенов/установок,
солёный хеш IP для регистрации, квоты и технический статус запроса. Записи очищаются
лениво при следующих обращениях. Данные передаются выбранному провайдеру по HTTPS.
