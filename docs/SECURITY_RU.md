# Защита Screen Helper 8.3

Ключ шифруется Windows DPAPI для текущей учётной записи. На диске хранится
`api_key_dpapi`, а не открытый `api_key`. Общего ключа в EXE нет. Сохранение сначала
шифрует ключ в памяти, затем атомарно заменяет файл. При ошибке шифрования прежний
конфиг остаётся на месте. Повреждённый ключ можно заменить через Setup.

Gemini и OpenAI имеют отдельные профили `gemini.local.json` и `openai.local.json`.
Последний выбранный профиль также сохраняется в `config.local.json`. Файлы
исключены из Git и релизов. Старый открытый ключ при чтении мигрирует в шифрованный
формат без открытой резервной копии. Старые версии новый формат не понимают:
распакуйте обновление отдельно. На другом ПК ключ нужно ввести заново.

DPAPI защищает сохранённый файл; программы под той же учётной записью и администратор
могут иметь доступ к ключу. Во время API-запроса открытый ключ нужен в памяти.
Не делитесь ключом. При утечке отзовите его у провайдера. Старые папки с настройками
и отчётами предыдущих версий автоматически не удаляются.

Снимок выполняется только по Ctrl+Alt+S и отправляется выбранному провайдеру.
В обычном режиме изображение, распознанные вопросы и история ответов на диск
не записываются. `last-result.json` содержит тип результата, безопасный код ошибки,
время и отдельные технические показатели. Проверки на синтетических вопросах
запускаются вручную и имеют отдельные отчёты.

HTTPS проверяет сертификат и имя сервера. Перенаправления API-запросов запрещены:
ключ и изображение не пересылаются на адрес из ответа сервера. Для OpenAI Responses
и Gemini Interactions указан `store=false`; это не отменяет политику данных провайдера.

Общий лимит — 60 секунд, можно выбрать 5–180. Старый безлимит заменяется на 60.
По лимиту дочерний процесс останавливается. Ctrl+Alt+X отменяет ожидание,
Ctrl+Alt+Q завершает помощник. Провайдер мог уже принять запрос и учесть оплату.
Одновременные управляемые запросы блокируются. Для временных 500/502/503/504
допускается один повтор внутри общего лимита; 429, ключ и доступ не повторяются.
После перегрузки, 429 или тайм-аута действует пауза. Резервная модель больше
не назначается автоматически; явно сохранённый резерв остаётся настройкой пользователя.

Во время ожидания выводится только число секунд. Ответ виден 15 секунд;
ошибка обозначается `?`, причина находится в панели. При отмене индикатор скрывается.
Неоднозначный или незавершённый ответ не подменяется случайным вариантом.

Процессы видны системе. Это защита ключей и устойчивость к сбоям, а не обход
прокторинга. Proctor Lab может намеренно обнаруживать ScreenHelper.

Проверки выполняются без платных API-вызовов и снимков рабочего стола:
реальный DPAPI, миграция, повреждение конфигурации, сбой шифрования, запрет
перенаправления на локальном HTTP-сервере, таймер, отмена и дочерние процессы.

Источники: [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata),
[ключи OpenAI](https://developers.openai.com/api/docs/guides/api-keys),
[Gemini Interactions](https://ai.google.dev/gemini-api/docs/interactions).
